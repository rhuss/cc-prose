## Implementation Approach

### Phase 1: Schema and Templates (Foundation)

Update the voice profile schema by adding new parameters to all 8 built-in templates. This is the foundation that all other changes depend on.

**Files modified**: All 8 `prose/knowledge-base/voice-templates/*.yaml`

**Per-template values** (researched from current template characteristics):

| Template | confidence | opening_style | transition_style | sentence_starters | emotional_range | self_correction | directness | specificity | paragraph avg |
|----------|-----------|---------------|-----------------|-------------------|----------------|----------------|------------|-------------|---------------|
| technical | 0.6 | direct | explicit | varied | flat | false | balanced | concrete | medium |
| conversational | 0.5 | anecdotal | organic | varied | dynamic | true | balanced | concrete | short |
| analytical | 0.7 | direct | explicit | formal-lead | flat | false | balanced | concrete | long |
| narrative | 0.5 | anecdotal | organic | varied | dynamic | true | balanced | concrete | medium |
| pov | 0.8 | contextual | organic | varied | dynamic | true | blunt | concrete | medium |
| reasoning | 0.6 | contextual | explicit | formal-lead | moderate | false | balanced | balanced | long |
| reference | 0.8 | direct | explicit | formal-lead | flat | false | balanced | concrete | medium |
| tutorial | 0.4 | contextual | organic | pronoun-heavy | moderate | true | hedged | concrete | short |

### Phase 2: Skill Updates (Consumers)

Update each skill that reads or writes voice profiles.

#### Content-Generator (SKILL.md)
- Add `confidence` interpretation in Step 3 (Apply Voice): map 0.0-0.3 to heavy hedging, 0.4-0.6 to moderate, 0.7-1.0 to assertive
- Add `paragraph_patterns` section: instructions for opening style, transition style, paragraph length
- Add `sentence_starters` to sentence pattern instructions
- Add `emotional_range`, `self_correction`, `directness` to personality injection
- Add `specificity` to elaboration instructions
- Update self-audit subagent prompt: when `measurements` section is present, append measurement validation instructions with deviation thresholds (>25% = flagged, 10-25% = informational, <10% = pass)
- Add old-format detection: if profile lacks `confidence`, warn and offer migration

#### Humanizer (SKILL.md)
- Add `confidence` and `directness` to voice matching: low confidence preserves hedging, high confidence removes it
- Add `paragraph_patterns` to rewrite guidance: respect opening style and transition preferences
- Add `emotional_range` and `self_correction` to personality preservation
- Add `specificity` to concreteness handling
- Update self-audit subagent prompt: same measurement validation as content-generator
- Add old-format detection: same logic as content-generator

#### Voice-Extractor (SKILL.md)
- Add extraction logic for all new human-readable parameters in the analysis workflow
- Add a new "Step: Compute Measurements" after parameter extraction that computes all 10 measurement fields from the corpus
- Add `sample_confidence` computation based on corpus size (< 1000 words = low, 1000-5000 = medium, > 5000 = high)
- Add measurements section to the output YAML template

#### Voice-Architect (SKILL.md)
- Add questions for new parameters in the interactive create workflow
- Add new parameters to the edit workflow
- Ensure no `measurements` section is generated (extractor-only)

#### Pre-Validator (SKILL.md)
- Add voice consistency checks for new parameters
- Add measurement deviation check when `measurements` present

### Phase 3: Migration Support

- Add old-format detection logic (check for `confidence` in `characteristics`)
- Add migration prompt with default values
- Add fallback behavior (use defaults silently when user declines)

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| LLM doesn't follow new params reliably | Medium | High | Measurement validation via self-audit provides a feedback loop |
| Template values are wrong for a voice | Low | Medium | Values are starting points; users can customize |
| Self-audit becomes too strict with measurements | Medium | Medium | Threshold tiers (25%/10%) prevent over-flagging |
| Old profiles break silently | Low | High | Detection and migration prompt at load time |
