AI coding assistants are everywhere now, and I have mixed feelings about them. They're fast at boilerplate, config files, and the kind of repetitive code nobody wants to write by hand. But "fast" and "correct" aren't the same thing, and I've merged AI suggestions that compiled fine and still did the wrong thing because I stopped reading carefully.

The productivity numbers are murky. GitHub says Copilot users accept about 30% of suggestions, but accepting a suggestion isn't the same as shipping working software. A 2024 study by Uplevel found no measurable difference in pull-request throughput between teams using AI assistants and teams that weren't. That doesn't mean the tools are useless. It means the benefits are harder to pin down than the marketing implies.

What actually worries me is the skill question. If junior developers learn to code by accepting suggestions instead of understanding them, we're building on a foundation nobody can debug. I don't have data for this yet, just a gut feeling from watching interns treat Copilot like an oracle.

The responsible path is boring but obvious: use the tools, review the output, write tests that catch the things the AI gets wrong. None of that requires a "paradigm shift" or a "culture of innovation." It requires discipline, which is less exciting but more useful.
